# 报告模式

选用报告骨架时完整阅读本文件，再只应用与当前任务匹配的模式。模式提供分析轴，不是强制章节；用户模板优先。

## A. 竞品与产品格局

适用于功能盘点、产品路线、竞争位置和差异化机会。

### 推荐分析轴

1. 市场级总判断：趋同在哪里，真正差异在哪里。
2. 需求/任务地图：能力对应什么用户问题，而不是只列功能名。
3. 对象档案：所有竞品用同一字段。
4. 真实体验：短链路、跨系统、可靠性、打断成本、控制感。
5. 商业验证：销量、活跃、付费、复用或口碑是否支持叙事。
6. 根因：技术、交互、权限、生态或商业模式中的结构性约束。
7. 差异化机会：选择可赢的链路和明确放弃项。

### 常用表

- `对象 | 价值主张 | 核心抓手 | 真实完成度 | 市场反馈 | 关键约束`
- `需求任务 | 对象 A | 对象 B | 对象 C | 格局结论`
- `能力大类 | 用户场景 | 领先者 | 差距/门槛`

先定义评价口径。“入口存在”“能跳转”“能填好信息”“能完成闭环”是不同成熟度，不得合并为“支持”。

## B. 用户反馈与口碑

适用于评论、社区、评测、访谈和长测材料。

### 推荐分析轴

1. 样本说明：平台、时间、筛选规则、样本量与偏差。
2. 分对象反馈：高频好评、典型差评、总体定性。
3. 任务归类：用户真正在哪些具体场景复用。
4. 口碑机制：为什么某些小功能形成习惯，宏大能力却被质疑。
5. 横向规律：共同好评、共同差评、各自一票否决项。
6. 购买/使用含义：口碑加分项是否真是决策主轴。

不要为了版式强行让每个对象拥有相同数量的好评和差评；只有样本允许时才对齐数量。入选反馈应满足“具体、可解释、多个独立来源重复”中的至少两项。把玩梗、围观、明确想用和真实复用分级，不把高赞想象当使用证据。

## C. 平台与生态健康度

适用于商店、开发者生态、内容/工具市场和开放平台。

### 推荐分析轴

1. 供给：总量、原创占比、来源结构、创作者集中度、批量行为。
2. 需求：下载/安装/调用/复用的转化，活跃用户渗透。
3. 分发：头部集中度、长尾可见性、新供给冷启动。
4. 质量与信任：维护、版本迭代、评价、审核、可解释性。
5. 生态循环：创作者能否获得反馈与收益，用户能否持续发现价值。
6. 商业模式：价值更可能出现在内容交易、工具服务、托管运行还是企业治理。

生态规模不是生态健康。至少同时看：原创供给、真实需求、分发效率、维护活力和正向循环。累计下载不能替代安装或调用；均值不能替代用户分布；总库存不能替代新增 cohort 的存活率。

行业类比必须比较机制，不只比较规模。说明相似点、差异点与类比失效处。

## D. 叙事演进与战略换挡

适用于官网、发布会、开发者大会、管理层表述和历代产品材料。

### 推荐分析轴

1. 时间线：按转折点划阶段，每阶段一句主叙事。
2. 传播载体：官网、发布会、开发者大会分别承担什么角色。
3. 叙事权重：首屏、篇幅、出场顺序、口号与演示环节。
4. 产品承载：叙事是否落到具体入口、场景和可验证能力。
5. 市场回声：销量、口碑、争议与后续收敛是否验证叙事。
6. 结构性发现：全行业的共同换挡、分化方向与下一变量。

官网适合证明导购主张，发布会适合观察行业论断和情绪峰值，开发者大会适合判断架构与生态意图。不要互相替代。每个对象使用同一字段，例如：`阶段 | 价值主张 | 标志性能力 | 传播权重 | 市场反馈 | 转向原因`。

## E. 战略建议与机会判断

以上任一报告都可在结尾使用，但建议必须从诊断推导，不能凭空追加。

按以下字段写建议：

| 字段 | 问题 |
| --- | --- |
| 机会 | 哪个未满足需求或结构性断点值得进入？ |
| 选择 | 做什么，不做什么？ |
| 机制 | 为什么这条路径能绕开当前约束？ |
| 前置条件 | 数据、能力、伙伴、权限或渠道需要什么？ |
| 风险 | 最可能失败在哪里？ |
| 验证 | 用什么最小实验和指标证明？ |
| 优先级 | 为什么现在做，为什么先做它？ |

优先建议“先跑通部分高价值闭环，再横向拓展”，除非证据显示网络效应或标准战要求必须先争规模。把愿景、策略、项目和指标分层，避免把“加强生态”“提升体验”这类方向词当行动方案。
